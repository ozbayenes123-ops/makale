# Rebuilding a Layout PDF into makale Structured Format

Use when the source is a journal-article or book-chapter PDF and `extract_pdf` output has no `[BODY]`/`pN` structure (raw per-page dump: footnotes interleaved after body text, superscript note markers glued to words, running heads repeated per page).

## Inspect before extracting

- Render sample pages (first, a mid body+footnotes page, last) with `page.get_pixmap(dpi=110-130)` and run `vision_analyze` on each to map: heading hierarchy, footnote style (page-bottom vs endnotes vs none), tables/figures, last-page content (map/index pages carry no prose).
- Database-platform covers (e.g. HeinOnline "AI SUMMARY" + citation-format pages) prepend the real article — find the first true article page by searching for the section headers and start extraction there.
- Enumerate footnote numbers present in the PDF before writing extraction code so you know the expected range and where OCR corrupts it.

## Layout extraction recipe (pymupdf `get_text('dict')`)

- Run probe/extract scripts from the project env: `cd C:/dev/mcp/makale && uv run python <script>.py` — pymupdf lives there; `import pymupdf` (the `fitz` name is deprecated). Long scripts with `&` or heredocs break the terminal tool — write the script to scratch and run the file.
- Span-size split: body spans are >= ~9pt, footnote/marker spans smaller. Running head and folio lines sit at y < ~62pt on a ~720pt-tall page. Footnote zone floor = min y0 of small-only blocks with y >= ~250pt; small-only blocks above the floor are stray fragments, not notes.
- In-text note markers are superscripts: either small spans inside big lines, or detect char-level rise in `get_text('rawdict')` (char origin y above the line base by > ~1.5pt). Re-attach each marker to its line and emit as `[fn N]`.
- When span-based marker recovery fights OCR (markers as separate offset glyphs, missing numbers), fall back to VISION ANCHORING: render every body page, fan out vision children to list per page the body markers as `{n, word}` pairs (word printed immediately before the superscript; exclude the bottom footnote block), save as `[[page, n, word], ...]` JSON, then place `[fn N]` into the rebuilt paragraphs. Place PAGE-SCOPED, never stream-globally — one missed anchor in a single forward stream chains into dozens of false misses. Per anchor search the page's paragraphs forward from a cursor with tiered patterns (strict word-boundary → loose substring → ~70% then ~55% prefix, case-insensitive) to survive OCR corruption, insert after the word's trailing alnum+punctuation run (mid-word tokens like `revelation [fn 91]s` fail QA), append to the page's last paragraph as fallback, then assert refs are complete, unique and ascending — fix the rare genuine dip with a surgical string replace, and spot-check any paragraph where a marker landed on a repeated word (`law`, `State`) in a garbled list by moving the token to its true anchor.
- Paragraph = text block, not line; join hyphen-split words when the continuation starts lowercase. Merge across pages only when the next block starts lowercase (uppercase-start blocks are new paragraphs, not continuations).
- Paragraph break inside a page = vertical gap > ~16.5pt, OR an indented first line whose predecessor ends in sentence punctuation — a 13.6pt gap threshold over-splits indented block quotations into one-line paragraphs. Compute the left margin per page with a Counter over x0: justified scans flip margins between pages (e.g. 77↔111) and one global margin misclassifies whole pages as continuations.
- Fan-out unit sizing for translation children: ~15 full paragraphs or ~30 footnotes per unit; a 19-paragraph body-only unit also completed cleanly, but any unit asked to echo hundreds of footnote definitions hit the output-token wall. Re-dispatch a truncated unit with body and footnote ranges split apart and 'output nothing but the file'.
- Footnote text: split notes inside a block with `(?<=\s|^)(\d{1,3})\.\s+(?=[A-Z"“'])`; an unnumbered block continues the previous note. Validate continuity 1..max against the captured set — gaps are almost always OCR digit/roman corruption (`I1.`=11, `l0.`=10, `O`/`0` swaps); normalize before numbering. Also scan the body dump for obvious OCR word corruption (`modem`→modern, `defmition`, `Uuniversity`) and repair it in the EN source, since numeric/proper-noun QA compares against it.
- Tables: `find_tables()` often returns 0 on scans. Rebuild the grid from span coordinates (bucket line y into ~4pt rows, group spans by column x ranges) AND render the page to PNG and read it via `vision_analyze`; reconcile both reads before translating. End-of-chapter maps/photos become a short figure note paragraph, never transcribed label text.

## Fidelity audit after extraction

- Never ship a translated OCR'd source with text the OCR ate. Heuristic first: flag every `pN:`/`N:` line whose text (after removing `[fn N]` tokens) does not end in sentence punctuation — a colon tail is legitimate (block quote follows) and a page-break continuation is legitimate; genuine mid-word stops and leaked page furniture (print page numbers glued into sentences) are the real hits.
- Scanned source, full audit: render EVERY body page (`get_pixmap(Matrix(2.4,2.4))`), build one per-page reference file listing the `pN`/`fnN` lines assigned to that page (keep page attribution from the build JSON and zip it against the CURRENT EN file's item order, asserting equal lengths — the EN file is the text of record, the JSON only maps pages), then fan out vision children of 6–8 pages each. Each child compares every ref line against the page image and writes JSONL corrections `{"id": "p45", "text": "<corrected full line, no pN: prefix>"}` with rules: flag only real truncation/missing words/leaked furniture/character garbage, keep `[fn N]` tokens at their true anchor words, never invent text the image cannot show, empty file when clean. Merge the JSONL into the EN file programmatically, re-diff the per-paragraph `[fn N]` sequences, re-translate only the affected `pN`/`N:` items, rerun `translate_apply`.
- Clean text-layer PDF, exact coverage test instead of vision: normalize EN corpus and every PDF line by removing soft-hyphen joins (`-\s+`), lowercasing and stripping all non-alphanumerics, then assert each PDF text line (len >= ~8) is a substring of the joined corpus. Whitelist deliberate exclusions: map/photo pages kept out of the body, running heads/folios, and lines whose content survives only as a translated idiom (e.g. `coup d'état` → `darbe`) — verify each flagged line by hand before calling it a miss. A naive sliding-window/shingle test produces dozens of false positives on dehyphenation and ligatures; only the full-string inclusion test gives a trustworthy zero.

## Serialize

- Emit `[TITLE]…[/TITLE]`, `[SUBTITLE]`, `[VAT_LABEL]`, `[BODY]`, `[SECTION id="…" title="…"]` per real heading, `pN:` paragraphs carrying `[fn N]` refs inline, `[/BODY]`, then `[FOOTNOTES]` / `N: text` / `[/FOOTNOTES]`. Headings are NOT paragraphs — keep them as SECTION titles so paragraph counts stay 1:1 in translation.
- Every `[fn N]` must have an `N:` footnote and vice versa (`citation_check` flags both directions; `article_docx` dumps unreferenced notes into a trailing "Dipnotlar" heading).
- Write `config.json` in the doc folder with `"source_layout_extraction": true` — `validate_pair` then skips strict paragraph/footnote count parity (correctly, since layout extraction is lossy); pin `expected_paragraphs`/`expected_footnotes` when you know the true counts.
- The numeric-coverage QA requires every digit run in the EN body to appear in the TR body — footnote reference numbers glued into words during extraction become phantom required digits; resolve markers into `[fn N]` (which the QA tolerates) before translating.
